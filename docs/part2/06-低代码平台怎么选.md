# 06 低代码平台怎么选：Dify / Coze / n8n

## 先回答一个更根本的问题：什么时候不该自己写代码

回到第01 章的连续谱：**如果你的任务是"多步但路径基本固定"的流程编排（谱上位置2），根本不需要模型自主规划，那就完全没必要自己写 Agent 代码。** 低代码平台的核心价值，就是把这类需求的开发成本压到几乎为零。

我自己在做企业 IM 智能问答机器人时，第一版就是直接用 Dify 搭的工作流——从立项到跑通只用了半天，如果一开始就选择自己写代码，至少要多花几天时间在"怎么解析大模型输出、怎么处理异常"这些工程细节上。**低代码平台不是"能力弱的替代品"，是"帮你把80% 常见工程细节都封装好了"的加速器。**

## 三大平台的定位差异

| | Dify | Coze | n8n |
|---|---|---|---|
| 核心定位 | AI 应用/工作流搭建（偏 LLM 应用） | 字节旗下 Agent/Bot 搭建平台 | 通用自动化工作流（不限于AI） |
| 强项 | 知识库/RAG 集成成熟，节点丰富，社区活跃 | 与国内社交平台（抖音/飞书等）生态打通方便，插件市场丰富 | 连接几乎所有第三方服务（邮件/数据库/API），AI 只是其中一种节点 |
| 部署方式 | 支持私有化部署（开源），也有云端版 | 主要云端（国内/国际版分离） | 支持私有化部署（开源），社区版免费 |
| 学习曲线 | 中等，节点逻辑清晰 | 较低，偏"面向业务人员" | 中等偏高，通用自动化概念更抽象 |
| 典型适用场景 | 企业内部知识问答、客服 Agent、内容生成流水线 | 面向 C 端的聊天机器人、社交平台 Bot |跨系统数据同步、非 AI 为主的自动化流程 + AI 节点点缀 |

## 我在真实项目里的选型经历

在企业 IM 机器人项目里，我经历了完整的"从 Dify 到自己写代码"的演进（Part 4 会有更详细的复盘），这里先说结论性的经验：

**Dify 工作流的局限，不是"能力不够"，是"调试和扩展的边际成本会突然变高"。** 具体来说：

- 节点之间传递变量的方式（必须用特定语法引用），一旦流程变复杂（我的场景有7-8个节点），排查一个变量没传对要花很长时间。
- 平台对接一些非标准 HTTP 返回格式时（比如 Content-Type 带额外参数），会有隐性的兼容性问题，而这类问题在自己写代码时可以直接调试网络请求，在低代码平台里只能靠猜。
- 当我需要同时支持"企微Agent 调用"和"其他系统调用"两条接入路径时，Dify工作流本质是"绑定在一个平台里的流程"，没法直接复用底层业务逻辑给别的入口用——这直接推动我转向"MCP Server + REST API 共享业务逻辑层"的自建架构。

## 决策框架：什么时候用低代码平台，什么时候自己写

```mermaid
flowchart TD
    Start[新Agent需求] --> Q1{团队里有没有<br/>工程师资源?}
    Q1 --没有--> LowCode[优先低代码平台<br/>业务人员也能维护]
    Q1 --有--> Q2{核心逻辑未来会不会<br/>被多个不同入口复用?<br/>如企微+网页+API}
    Q2 --会--> Custom[自建服务，<br/>业务逻辑独立于任何单一平台]
    Q2 --不会，单一入口--> Q3{预计流程复杂度<br/>会超过10个节点<br/>或涉及复杂条件分支吗?}
    Q3 --会--> Q4{团队能接受<br/>较高的调试成本吗?}
    Q4 --能接受--> LowCode2[低代码平台起步<br/>做好"未来可能要重构"的预期]
    Q4 --不能接受--> Custom
    Q3 --不会，简单流程--> LowCode3[低代码平台，<br/>性价比最高的选择]
```

## 一个务实的建议：低代码平台是原型验证的最佳工具，不是终态判断的依据

不管你最终会不会自己写代码，**先用低代码平台把流程验证通一遍，几乎总是性价比最高的第一步**——它能在几小时内告诉你"这个业务逻辑到底行不行得通"，而不需要你先花几天搭建工程框架。等验证通过、需求边界稳定之后，再决定要不要为了性能、可维护性、多入口复用而迁移到自己的代码架构。**我自己的经验是：把低代码平台当 MVP 验证工具用，而不是当成"这个项目就该长期用这个平台"的决定。**

## 产品经理清单

> - [ ] 我选低代码平台的理由，是"团队没工程师资源"，还是"图省事，没认真评估未来的复用/扩展需求"？
> - [ ] 如果未来这个逻辑要被多个入口复用（网页+IM+API等），我现在用的低代码平台能不能把"核心逻辑"和"具体某个平台的对接细节"解耦？
> - [ ] 我有没有把低代码平台的原型验证结果，当成了"这个方案能不能落地"的证据，而没有区分"业务逻辑是否可行"和"这个平台是否该长期用"这两件事？
